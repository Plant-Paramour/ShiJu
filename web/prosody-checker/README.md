# 诗词格律检查器

这是从 `evaluation/evaluate.py` 抽取并改写的独立浏览器端格律检查系统。它检查唐诗、宋词、俳句和排律，展示逐字平仄、错误位置、韵组，以及结构、平仄和押韵三项分数。

## 运行

从仓库根目录启动静态服务器：

```bash
python -m http.server 8000 --bind 127.0.0.1
```

访问 `http://127.0.0.1:8000/web/prosody-checker/`。不能直接以 `file://` 打开页面，因为 ES Module 和 JSON 数据请求需要 HTTP。

运行核心测试：

```bash
node --test web/prosody-checker/tests/core.test.mjs
```

## 功能参数

| 参数 | 选项 | 行为 |
| --- | --- | --- |
| 体裁 | 唐诗、宋词、俳句、排律 | 切换对应评分器。 |
| 韵书 | 中华新韵、平水韵、词林正韵、中华通韵 | 决定平仄和韵部查询结果。 |
| 唐诗字数 | 五言、七言 | 指定每句字数。 |
| 唐诗篇式 | 绝句、律诗 | 指定四句或八句。 |
| 宋词词牌 | 当前六个模板 | 从 `Songci_Meter/` 选择模板。 |
| 宋词变体 | 词牌所含变体 | 指定逐字平仄、阕结构和韵组。 |
| 多音字 | 严格、放行 | 严格模式要求所有读音均合法；放行模式只需存在合法读音。默认放行。 |
| 拗救 | 关闭、开启 | 控制唐诗、排律和俳句是否接受相邻平声拗救。默认关闭，宋词不适用。 |
| 正文 | 用户粘贴文本 | 支持标点或换行分句，也兼容含 `[content]` 的生成结果。 |

排律自动识别五言或七言，并检查不少于十句的偶数句；俳句固定按三行 5-7-5 检查，不显示额外选项。

## 标注与评分

- 多音字：当前韵书中存在多个“平仄 + 韵部”组合时显示黑色粗体。严格模式要求所有读音合法，放行模式只要求一个读音合法。
- 错误字：不满足当前位置格律时显示红色粗体；同时为多音字时红色优先。
- 结构分：宋词按字数正确的模板分句占比计算；唐诗按实有句中字数正确的占比计算，句数错误时最高 50 分。排律和俳句按相同语义扩展。
- 平仄分：合规位置数除以参与检查位置数，再乘 100。
- 押韵分：每个韵组中命中最多共同韵部的韵脚数除以韵脚总数，再乘 100；多个韵组取平均。

结构问题除计入结构分外也会显示文字提示。论文批量评估中的加权总分仍保留在 `evaluation/`，本页面不展示。

唐诗和排律检查二四六、末字收束、孤平、三连平/三连仄与押韵。孤平检查会考虑相邻平声救位；拗救关闭时只标记实际偏离二四六的位置，避免级联误标，开启时符合拗救条件的偏差可以通过。宋词严格使用所选模板，模板中的 `中` 原样展示并允许平仄。俳句的 5-7-5、孤平、三连同和韵脚集中度是从现有汉俳业务约束推导的前端规则，不属于论文原始 evaluator 的覆盖范围。

## 架构与部署

`core.js` 只包含解析和评分纯函数，`app.js` 负责页面状态、按需数据加载与渲染。韵书首次选择时加载一次并缓存；正文不上传，所有计算均在浏览器完成。

桌面端检查前采用紧凑居中的输入面板，检查后切换为左右工作区；逐句结果自适应多列排列。常规诗词保持在单屏工作区内，超长排律仅滚动结果面板，不延长整个页面。窄屏设备自动改为单列。

当前四本韵书合计约 355 KB，词牌模板约 6 KB，单次作品通常只有几十至数百字。对计划中的 2 核 2G 服务器，静态前端是更合理的方案：Nginx 或 Caddy 只需提供静态文件、gzip/Brotli 和长期缓存，不需要常驻 Python/Node 评分服务，也没有并发会话状态。

部署文件必须保持以下相对结构：

```text
Rhyme/
Songci_Meter/
web/prosody-checker/
```

建议为 JSON、CSS 和 JavaScript 开启压缩与缓存；HTML 使用短缓存。未来只有在引入账号、历史记录、作品持久化、私有韵书或统一审计时，再把保存与鉴权放到后端，评分核心仍可复用 `core.js`。

## 核心接口

公开函数包括 `buildLexicon`、`parsePoem`、`flattenMeter`、`formatMeterTemplate`、`evaluateSongci`、`evaluateTang`、`evaluatePailv` 和 `evaluateHaiku`。完整参数和返回字段见 `../../docs/API.md` 的“浏览器端格律检查接口”。
